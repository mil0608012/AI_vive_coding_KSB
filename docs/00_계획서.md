# 단백질 상호작용 분석 웹앱 (ProtInteract) 구축 계획

## Context
- 목적: 타겟 단백질(복합체) + 후보 상호작용 단백질들을 UniProt ID만으로 AlphaFold Server 입력 JSON으로 자동 변환 → 모델링 결과를 받아 "진짜 상호작용처럼 보이는" 모델만 1차 필터 → PyMOL/ChimeraX/FoldX로 상호작용(수소결합, 염다리, ΔΔG, RMSD) 분석·시각화 → 표(엑셀/CSV)와 그림(PNG)으로 저장하는 **로컬 실행 웹앱**.
- 결정된 조건 (사용자 답변):
  - 모델링은 **AlphaFold Server에 수동 업로드** (로컬 GPU 없음; 현재 PC는 RTX 3060 Laptop → AF3 로컬 불가).
  - 배포는 **로컬 PC 실행 웹앱**.
  - 후보 규모가 가변적(실험으로 좁힌 소수 ↔ 전사인자 전체 스크리닝) → **"프로젝트 단위 + 배치 분할 + 작업 큐 관리"** 구조로 소규모 작업을 여러 번 반복하는 방식으로 설계.
- 현재 작업 폴더는 사실상 비어 있음(강의 노트 rtf만 존재) → 새 프로젝트로 시작. 환경: Windows 11, Python 있음(버전 확인 필요), Node 없음, WSL 있음, PyMOL/ChimeraX/FoldX 미설치.

## 약관 관련 답변 (AlphaFold Server 자동 업로드)
AF Server 이용약관은 자동화/프로그램 접근을 허용하지 않고(공식 API 없음, 구글 계정 로그인 필요, 비상업적 용도 한정), 로그인 세션을 대신 조작하는 업로드 반복은 약관 위반 위험이 큼 → **자동 제출은 구현하지 않음.** 대신 노동을 최소화하는 합법적 방법:
1. 앱이 **여러 잡을 한 JSON 파일에 묶어** 생성(AF Server는 JSON 임포트로 다중 잡 지원) → 사용자는 파일 1개를 업로드하는 것으로 끝.
2. 하루 쿼터(현재 약 20잡/일, 변동 가능 — 구현 시 확인)에 맞춰 **자동으로 일자별 배치 분할**(`batch_01.json`, `batch_02.json` …)하고 제출 현황 체크리스트 제공.
3. 결과 zip을 **폴더에 드롭/업로드하면 잡 이름으로 자동 매칭**.

## 아키텍처
- **Python 단일 스택** (Node 불필요, 바이브코딩 유지보수 쉬움): UI = **Streamlit**, 3D = **py3Dmol/Mol\*** 임베드(브라우저 내 인터랙티브 확인), 저장 = **SQLite + 프로젝트 폴더**.
- 핵심 로직은 UI와 분리된 패키지 `protinteract/`로 작성 → 나중에 FastAPI/React로 교체 가능.
- 외부 프로그램은 **설정 화면에서 경로 지정**(subprocess 호출): PyMOL(`pymol -cq` headless 이미지 렌더), ChimeraX(`--nogui --script`, 선택), FoldX(학술 라이선스 바이너리 + `rotabase.txt`, 재배포 불가 → 사용자가 직접 설치).

```
protinteract/
  app.py                    # Streamlit 진입점 (페이지: 프로젝트/입력/배치/결과/분석/리포트/설정)
  core/
    uniprot.py              # 1단계: UniProt REST 조회
    af_json.py              # 1단계: AF Server JSON 생성·검증·배치 분할
    af_results.py           # 2단계: 결과 zip 파싱 (confidences, cif)
    scoring.py              # 2단계: 지표 계산·등급화
    structure_io.py         # cif→pdb 변환, 체인 매핑
    interface.py            # 3단계: H-bond/염다리/소수성/BSA 계산
    foldx_runner.py         # 3단계: RepairPDB, AnalyseComplex, (옵션)BuildModel
    rmsd.py                 # 3단계: 모델 간/참조구조 RMSD
    render_pymol.py         # 3·4단계: PNG 렌더
    report.py               # 4단계: xlsx/csv/HTML 리포트
    db.py, config.py
  tests/  data/  projects/<name>/{input,batches,results,analysis,figures,report}
```

## 단계별 구현 계획

### 1단계 — UniProt → AF Server JSON
- 입력: 타겟 복합체 구성원(UniProt ID + 복제수 `count`) 목록, 후보 UniProt ID 목록(붙여넣기/CSV/키워드 쿼리, 예: 전사인자는 UniProt `keyword:KW-0805` + human 필터로 일괄 수집).
- `uniprot.py`: `https://rest.uniprot.org/uniprotkb/{id}.json` 호출 → 서열, 유전자명, 종, 길이, 도메인/신호펩타이드/무질서 영역 feature. 아이소폼(`P12345-2`), obsolete/merged ID, 캐시(로컬 JSON) 처리.
- `af_json.py`: AF Server 포맷 생성 — `[{"name","modelSeeds":[],"sequences":[{"proteinChain":{"sequence","count"}}],"dialect":"alphafoldserver","version":1}]`.
  - 잡 이름 규칙: `{target}__{candidate}` (결과 매칭 키).
  - 타겟 복합체는 모든 잡에 공통 포함 + 후보 1개씩 추가(후보 1개당 1잡).
  - 지원 옵션: 이온(예: 징크핑거 Zn²⁺), DNA 체인(전사인자 DNA 결합), PTM(인산화 등), 도메인 트리밍(토큰 한도 5,000 초과 시 경고·자동 제안), 시드 지정.
  - 사전 검증: 총 토큰 수, 비표준 문자, 중복 잡.
- UI: 입력 → 미리보기 표 → "배치 N개로 분할" → JSON 다운로드 + 제출 체크리스트.
- 사용자가 먼저 한 번 수동으로 JSON 임포트가 실제로 되는지 확인하도록 가이드(포맷 변경 대비).

### 2단계 — 결과 수집 및 1차 필터
- `af_results.py`: AF Server 결과 zip 파싱 — 잡당 5모델 `*_model_N.cif`, `*_summary_confidences_N.json`(ptm, iptm, chain_pair_iptm, chain_pair_pae_min, ranking_score, has_clash, fraction_disordered), `*_full_data_N.json`(PAE 행렬, atom_plddts). 실제 파일명/키는 첫 결과로 확인 후 파서 고정.
- `scoring.py` 지표 (후보-타겟 **쌍 단위**로 계산 — 3체인 이상일 때 전체 ipTM은 희석되므로 `chain_pair_iptm` 사용):
  - ipTM, 쌍 chain_pair_iptm, ranking_score, 쌍 chain_pair_pae_min
  - 인터페이스 pLDDT 평균, 인터페이스 접촉 잔기 수(Cβ ≤ 8 Å 기준), BSA
  - **ipSAE / pDockQ2** (무질서 꼬리 때문에 ipTM이 낮게 나오는 TF 등에 유리, PAE 기반 직접 계산)
  - has_clash, 5개 모델 간 인터페이스 일관성(5개 중 몇 개가 같은 결합 모드인지, 인터페이스 RMSD)
- 등급화(설정 가능한 임계값, 기본값 예시): **High** ipTM ≥ 0.8 & 쌍 PAE_min 낮음 & clash 없음 / **Medium** 0.6–0.8 / **Low·Reject** 그 외. 기본값은 가이드라인일 뿐 → **음성 대조군(알려진 비상호작용 단백질 쌍)과 양성 대조군(알려진 복합체)을 같이 돌려 임계값 보정**하는 기능 포함(AF3 위양성 방지의 핵심).
- UI: 정렬/필터 가능한 순위표, PAE 히트맵, 통과 모델 선택·수동 오버라이드. 통과 모델만 3단계로 전달.

### 3단계 — 구조 시각화 및 상호작용 분석
- 구조 준비: CIF→PDB 변환, 체인 ID 정리(`structure_io.py`).
- **상호작용 검출** (`interface.py`, Biopython `NeighborSearch` + 기하 계산을 기본으로, PLIP은 교차검증용 선택):
  - 수소결합: 공여체–수용체 거리 ≤ 3.5 Å + 각도 기준
  - 염다리: 양/음전하 잔기 말단 원자 간 ≤ 4.0 Å (Arg/Lys/His ↔ Asp/Glu)
  - 소수성 접촉, π-stacking, 인터페이스 BSA
  - 잔기 단위 상호작용 테이블 출력
- **FoldX** (`foldx_runner.py`): `RepairPDB` → `AnalyseComplex`(인터페이스 결합 에너지, 잔기별 기여) 로 후보 간 비교·순위화. **ΔΔG는 변이가 있을 때만 의미가 있으므로** 선택 기능으로 `BuildModel`/`Pssm` 기반 인터페이스 핫스팟 **in-silico 알라닌 스캔**(ΔΔG) 제공. 주의 문구 표시: AF 모델에 대한 FoldX 절대값은 거칠어 후보 간 *상대 비교* 용도.
- **RMSD** (`rmsd.py`): (a) 모델 5개 간 인터페이스 RMSD(일관성), (b) PDB 참조구조가 있으면 타겟 복합체 기준 정렬 후 후보 RMSD.
- **시각화**: 웹에서 py3Dmol로 인터랙티브(체인별 색, pLDDT 색, 인터페이스 잔기 스틱, H-bond 점선 노란색, 염다리 표시) + `render_pymol.py`가 동일 장면을 PyMOL headless로 고해상도 PNG 렌더. ChimeraX는 어댑터 형태로 후순위(Windows headless 렌더 지원은 구현 시 확인).

### 4단계 — 데이터 정리 및 저장
- `report.py`: 후보별 요약표(`xlsx`: Summary / Interface residues / H-bonds / Salt bridges / FoldX / RMSD 시트 + CSV), 후보별 PNG(전체 구조·인터페이스 클로즈업·PAE 플롯), 프로젝트 전체 HTML 리포트, 재현을 위한 설정/버전/임계값 기록(`analysis_manifest.json`).
- 저장 구조는 `projects/<name>/` 아래 단계별 폴더, 다시 열면 DB에서 복원.

## 개발 순서 (마일스톤)
1. **M0 환경**: Python 버전 확인, 가상환경, Streamlit/Biopython/py3Dmol/pandas/openpyxl 설치, PyMOL(open-source 빌드, conda 권장)·FoldX 설치 여부 점검, 설정 화면.
2. **M1 (1단계)**: UniProt 조회 + JSON 생성/배치 분할 + 테스트(알려진 ID 몇 개로 단위 테스트). → 사용자가 AF Server에 실제 업로드 테스트.
3. **M2 (2단계)**: 실제 AF Server 결과 zip 1~2개를 받아 파서 확정 → 지표/등급/순위표/대조군 보정.
4. **M3 (3단계)**: 상호작용 검출 → PyMOL 렌더 → FoldX 연동 → RMSD.
5. **M4 (4단계)**: 리포트·이미지 일괄 출력, 프로젝트 저장/재열기, 사용 문서(README, 한국어 가이드).

## 핵심 리스크
- AF Server JSON 포맷/쿼터/결과 파일 구조가 바뀔 수 있음 → 파서·생성기를 얇은 어댑터로 두고 샘플 파일로 회귀 테스트.
- FoldX는 라이선스 필요(학술 무료, 재배포 금지), PyMOL/ChimeraX도 설치 경로 다양 → 미설치 시 해당 기능만 비활성화(앱은 계속 동작).
- AF 기반 상호작용 예측의 위양성 → 대조군 보정 + 모델 간 일관성 + ipSAE를 필터에 반영, 최종 판단은 실험 검증이 필요하다는 안내 문구.
- 무질서 영역이 많은 전사인자 → 도메인 트리밍 옵션과 ipSAE로 대응.

## 검증 방법 (end-to-end)
1. 알려진 상호작용 쌍(양성) + 무관한 쌍(음성)을 UniProt ID로 입력 → 생성 JSON을 AF Server 임포트에서 오류 없이 수락되는지 확인.
2. 실제 결과 zip을 앱에 올려 지표가 AF Server 화면 수치(ipTM, ranking score)와 일치하는지, 양성은 통과·음성은 탈락하는지 확인.
3. 통과 모델의 H-bond/염다리 수치를 PyMOL `find`/ChimeraX `hbonds` 결과와 샘플 몇 개로 교차 검증.
4. FoldX AnalyseComplex가 정상 실행·파싱되는지, 알라닌 스캔 ΔΔG 부호가 합리적인지 확인.
5. 리포트(xlsx + PNG + HTML) 생성 후 프로젝트를 닫고 다시 열어 복원되는지 확인.
6. `pytest`로 core 모듈 단위 테스트, `streamlit run app.py`로 전체 흐름 수동 점검.
