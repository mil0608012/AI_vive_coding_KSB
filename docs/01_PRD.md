## 1. 배경과 문제 ✅
- 타겟 단백질 복합체와 상호작용할 것으로 예측되는 후보 단백질들의 구조를 AlphaFold Server로 모델링하고 분석하는 일이 필요하다.
- 현재는 서열 수집, JSON 작성, 결과 선별, 시각화, 상호작용 계산, 정리를 모두 수작업으로 해야 해서 시간이 많이 든다. 프로그램으로 이 소요 시간을 줄이고 효율적으로 분석하는 것이 목적이다.
- 프로그램은 하나이지만 두 구간으로 나뉘어 동작한다.
  - **전반부**: UniProt ID 입력 → 서열 수집 → AF Server 업로드용 JSON 파일 생성
  - (중간) 사용자가 AF Server에서 직접 모델링을 실행하고 결과 zip을 내려받는다. 프로그램 밖에서 이루어진다.
  - **후반부**: 결과 zip 입력 → 1차 필터 → 분석·시각화 → 표·그림 저장
- 두 구간은 프로젝트 기록으로 이어져서, 중간에 며칠이 걸려도 결과를 원래 후보와 자동으로 맞춘다.

## 2. 목표와 비목표 ✅

**목표**
1. UniProt ID로 서열을 받아 AF Server용 JSON을 자동으로 만든다.
2. 결과 중 상호작용하는 것처럼 모델링된 것만 1차로 거른다.
3. 거른 모델을 시각화하고 수소결합, 염다리, ΔΔG, RMSD 등 상호작용을 확인한다.
4. 데이터는 표로, 그림은 이미지로 저장한다.
5. AF Server 유래가 아닌 기존 구조 파일도 직접 올려 분석할 수 있다.

**비목표** (이번 버전에서 하지 않는 것)
- **로컬 AlphaFold 구동**: 장비(GPU) 문제로 사용하지 않는다.
- **AF Server 자동 업로드와 결과 자동 다운로드**: 공식 API가 없고 자동화에 한계가 있어 보류한다. 업로드와 다운로드는 사용자가 직접 하고, 프로그램은 JSON 생성과 결과 분석을 맡는다.
- **다중 사용자 서버형 서비스**: 한 사람이 자기 PC에서 로컬로 쓰는 분석 웹 프로그램으로 기획한다. 여러 명 접속, 계정, 서버 배포는 다루지 않는다.
- **상호작용의 확정 판정**: 결과는 후보 선별용이며, 최종 확인은 실험으로 한다.

## 3. 사용자와 사용 상황 ✅

**사용자**
- 한 사람이 자기 PC에서 혼자 사용한다. 계정이나 여러 명 동시 접속은 고려하지 않는다.
- 단백질 구조분석을 하는 연구자이다. 연구모임 구성원이 각자 자기 PC에 설치해서 쓸 수 있으며, 각자 독립적으로 사용한다.
- 사용자는 PyMOL, ChimeraX 같은 단백질 구조 시각화 프로그램을 써 본 경험이 있다고 가정한다. 따라서 화면에서 용어 설명은 간단한 안내 수준으로 한다.

**사용 상황**
1. **좁혀진 후보 분석**: 다른 실험으로 후보를 소수로 줄인 뒤, 그 후보들의 상호작용 구조를 분석한다.
2. **광범위 스크리닝**: 전사인자 전체 같은 많은 후보를 타겟과 반응시켜, 상호작용하는 단백질을 찾는다(동정).
   - 후보가 많으면 하루 쿼터에 맞춰 여러 날에 걸쳐 나눠서 진행한다.
3. **기존 구조 파일 분석**: AF Server 유래가 아닌 구조 파일(PDB 등록 실험 구조, 이전에 받아 둔 결과, 다른 프로그램으로 만든 모델)을 직접 올려 분석, 시각화, 저장 기능을 이용한다. (AF 점수가 없으면 1차 필터는 건너뛴다.)

**실행 환경**
- 사용자의 Windows PC에서 로컬로 실행하는 웹 프로그램이다. 브라우저에서 열리지만 인터넷에 공개하지 않는다.
- 서열 조회(UniProt)와 필요 시 참조구조 조회에 인터넷을 사용한다. 결과 분석과 시각화는 인터넷 없이 가능하다.

## 4. 기능 요구사항 🔶 (제안 단계, 미검토)
우선순위: **P0** = 없으면 쓸 수 없음, **P1** = 중요, **P2** = 있으면 좋음. 우선순위는 전부 [제안].

**4.1 입력과 JSON 생성** (전반부)
- P0: 타겟 복합체 구성 단백질(UniProt ID, 복제수)과 후보 목록을 입력할 수 있다. [말씀]
- P0: UniProt에서 서열을 자동으로 가져와 AF Server 호환 JSON을 만든다. [말씀]
- P0: 후보가 많으면 하루 쿼터 단위로 나눠 여러 JSON 파일(배치)로 만든다. [계획]
- P1: 배치별 제출·완료 현황을 기억하고 체크리스트로 보여준다. [계획]
- P1: 이온(Zn²⁺ 등), DNA 체인, 도메인 트리밍을 선택할 수 있다. [계획]
- P2: 키워드(예: 전사인자)로 후보를 일괄 수집한다. [계획]

**4.2 결과 수집과 1차 필터** (후반부)
- P0: AF Server 결과 zip을 올리면 잡 이름으로 자동 매칭하고 점수를 읽는다. [계획]
- P0: ipTM 등 신뢰도 지표로 상호작용 가능성이 높은 모델만 거르고 순위표를 보여준다. [말씀]
- P1: 기준값(임계값)을 사용자가 조정할 수 있고, 통과 여부를 수동으로 바꿀 수 있다. [계획]
- P1: 알려진 양성·음성 대조군으로 기준값을 보정한다. [계획]
- P2: ipSAE, pDockQ2 같은 추가 지표, PAE 히트맵 [계획]

**4.3 분석과 시각화** (후반부)
- P0: 통과한 모델을 3D로 보고, 인터페이스를 표시한다. [말씀]
- P0: 수소결합과 염다리를 찾아 잔기 단위 표로 보여준다. [말씀]
- P1: RMSD(모델 간, 참조구조 대비)를 계산한다. [말씀]
- P1: FoldX로 결합 에너지를 계산해 후보를 비교한다. [말씀]
- P2: 인터페이스 알라닌 스캔 ΔΔG, ChimeraX 연동 [계획]

**4.4 정리와 저장** (후반부)
- P0: 후보별 요약표를 엑셀/CSV로 저장한다. [말씀]
- P0: 구조 그림을 PNG 이미지로 저장한다. [말씀]
- P1: 프로젝트를 저장하고 다시 열 수 있다. [계획]
- P2: 전체 HTML 리포트 [계획]

**4.5 3장 검토에서 새로 생긴 항목 (우선순위 미정)** [제안]
- 구조 파일(`.cif`/`.pdb`) 직접 입력: AF 점수가 없으면 1차 필터를 건너뛰고 분석으로 진행한다. 직접 올린 구조는 타겟 체인과 후보 체인을 사용자가 지정해야 한다.
- 구조 파일 여러 개를 담은 zip 입력: AF 결과 zip과 구분해서 처리한다.
- 통과 모델을 `.pdb`/`.cif`로 내보내 PyMOL·ChimeraX에서 이어서 열 수 있게 한다.
- 프로젝트 생성 시 "서열부터 시작"과 "구조 파일부터 시작" 중 선택한다.

## 5. 비기능 요구사항 🔶 (제안 단계, 미검토)
- Windows 11 로컬 실행. 인터넷 사용 범위는 3장 실행 환경을 따른다. [제안]
- PyMOL, FoldX가 없어도 앱은 동작하고 해당 기능만 비활성화된다. [계획]
- 한국어 화면과 안내를 제공한다. [제안]
- 후보 수십~수백 개를 다루되, 분량은 AF Server 하루 쿼터에 맞춰 나눠서 처리한다. [말씀+계획]
- 같은 입력이면 같은 결과가 나오고, 사용한 설정과 버전을 기록한다. [계획]

## 6. 성공 기준 🔶 (제안 단계, 미검토)
이게 되면 완성이라고 볼 기준. 모두 [제안].
1. 알려진 상호작용 쌍은 필터를 통과하고, 무관한 쌍은 탈락한다.
2. 생성한 JSON이 AF Server에서 오류 없이 받아들여진다.
3. 앱의 점수가 AF Server 화면의 ipTM, ranking score와 일치한다.
4. 수소결합·염다리 결과가 PyMOL 등 기존 도구 결과와 샘플 몇 개에서 일치한다.
5. UniProt ID 입력 → JSON 생성(전반부), 결과 zip 업로드 → 표·그림 저장(후반부)이 하나의 프로젝트로 이어진다. (AF Server 단계는 사용자가 직접 수행)

## 7. 제약과 가정 🔶 (제안 단계, 미검토)
- AF Server: 공식 API가 없고, 이용약관상 자동화에 제약이 있으며, 비상업적 용도 한정, 하루 쿼터가 있다(약 20잡/일, 변동 가능). 이런 이유로 업로드·다운로드 자동화는 보류한다. [계획]
- 사용자 PC에 고성능 GPU가 없다. [말씀]
- FoldX는 학술 라이선스를 사용자가 직접 받아야 하고, PyMOL/ChimeraX도 별도 설치가 필요하다. [계획]
- AF 모델 기반 결과는 위양성이 있을 수 있고, FoldX 절대값은 거칠어 후보 간 상대 비교에 쓴다. [계획]
